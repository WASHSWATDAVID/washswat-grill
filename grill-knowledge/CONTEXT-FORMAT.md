# CONTEXT.md 포맷

`CONTEXT.md`는 이 프로젝트의 **용어 사전**이다. 도메인 전문가(=데이비드 본인과 협업자)에게 의미 있는 단어와 그 정의만 담는다.

## 기본 구조

```markdown
# Context — [프로젝트 이름]

이 프로젝트에서 사용하는 용어와 개념의 사전. 새 용어는 `grill-knowledge` 스킬을 통해 추가된다.

## 핵심 용어

### [용어]
[1~3문장 정의. 무엇인지, 왜 중요한지, 인접 용어와 어떻게 다른지.]

**예시**: [구체적 예시 한 줄]
**관련 용어**: [같이 보면 좋은 다른 용어들]

---

### [다음 용어]
...
```

## 좋은 항목 예시

```markdown
### WWG

WashSwat가 진행 중인 메인 딜의 상대 회사. 런드리고와의 합병 구조에서 인수 대상.

**예시**: "WWG가 인사이트 검토를 마치면 LOI 단계로 넘어간다"
**관련 용어**: 런드리고 합병, 인사이트, LOI
```

```markdown
### 인사이트

법무 자문 그룹의 약칭. 데이비드의 딜에서 외부 법률 검토를 수행하는 주체.

**예시**: "5월 15일 인사이트에 검토 의뢰 메일 발송"
**관련 인물**: 정유선 변호사, 이경윤 변호사
```

## 나쁜 항목 예시

❌ 너무 일반적 — 도메인 사전이 아니라 위키:
```markdown
### M&A
회사 간 인수합병을 의미한다...
```

❌ 구현 디테일 — `docs/agents/`로 가야 함:
```markdown
### Notion Todo
Status, Priority 필드를 가진 데이터베이스로 ...
```

❌ 누구나 아는 사실:
```markdown
### 이메일
전자 메시지를 보내는 수단으로...
```

## 작성 원칙

1. **이 프로젝트에서 자주 나오면서**, **외부인이 모르는** 단어만 등록
2. 정의는 **3문장 이내** — 길어지면 `docs/knowledge/`로 분리
3. 예시는 **이 프로젝트 안에서 실제 발생한 일**로
4. 관련 용어를 항상 cross-link — 사전이 그래프처럼 연결되게
5. 인물/회사처럼 정보가 많은 항목은 **여기에 한 줄**만 두고, 자세한 건 `docs/knowledge/people.md` 같은 곳으로 분리

## 충돌 발생 시

같은 용어가 다른 의미로 두 번 나타나면 즉시 사용자에게 알리고, 둘 중 하나를 골라 다른 단어로 분리한다.

> "'담당자'가 의사결정자와 실무자 모두로 쓰였다. 둘로 나누자: '의사결정자(DM)' / '실무 담당자(Operator)'."
