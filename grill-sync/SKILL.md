# Grill Sync

세션 중 **중요한 사실이 바뀌었을 때** 큐에 쌓지 않고 즉시 해당 파일을 업데이트한다.

grill-knowledge의 배치 모드(큐 누적)와 다르게, grill-sync는 **즉시 인터럽트 → 확인 → 파일 업데이트** 순서로 동작한다.

---

## 즉시 인터럽트 조건

다음 중 하나라도 감지되면 grill-sync가 발동된다 (grill-knowledge에서 자동 위임 또는 사용자 직접 호출):

| 조건 | 예시 발언 | 우선순위 |
|---|---|---|
| **MT-5: 주주 입장 변경** | "X가 구주 매각에 참여하기로 했어", "Y가 철회했어", "Z는 불참으로 바뀌었어" | 최고 — 항상 즉시 |
| **MT-2: 기존 사실과 모순** | "아 그게 아니라 원래 A였어", "CONTEXT에 잘못 박혀 있어" | 높음 — 즉시 |
| **MT-2: 금액/지분율 변동** | "단가가 X원으로 바뀌었어", "지분율이 Y%가 됐어" | 높음 — 즉시 |
| **MT-1: 결정 번복** | "아까 그 결정 취소야", "X 말고 Y로 가기로 했어" | 높음 — 즉시 |

## 동작 플로우

### Step 1. 인터럽트 알림

감지 즉시:

```
⚡ [변경 내용] 감지됨.

예: ⚡ [김영희] 구주 매각 참여 → 불참으로 변경 감지됨.

지금 업데이트할까요?
→ 예 (지금 바로)
→ 나중에 (큐에 추가)
```

### Step 2. 업데이트 대상 파일 확인

조건에 따라 업데이트 대상을 자동 결정:

**MT-5 (주주 변경)** → IL-3 강제: 반드시 3곳 동기화
1. `harnesses/shareholders/per-holder/<주주>.md` — 표준 6개 섹션
2. `harnesses/shareholders/CONTEXT.md` — 마스터 매트릭스 해당 행
3. `harnesses/shareholders/STATUS.md` — 구주 확보 현황 합계

**MT-2 모순/금액 변동** → 해당 CONTEXT.md 또는 knowledge/ 파일
- 어느 harness 파일인지 특정 후 업데이트
- 모순이면 기존 내용과 새 내용 둘 다 보여주고 어느 쪽이 맞는지 confirm 받기

**MT-1 번복** → 해당 ADR 파일
- 기존 ADR의 상태를 "번복됨"으로 표시
- 새 결정으로 신규 ADR 또는 STATUS.md 업데이트

### Step 3. 변경 내용 미리보기

업데이트 전 변경 내용을 보여준다:

```
업데이트 미리보기:

📄 harnesses/shareholders/per-holder/김영희.md
  섹션 3 (구주 처리 의향):
  변경 전: 참여 의향 (2026-05-10 확인)
  변경 후: 불참 (2026-05-29 확인)

📄 harnesses/shareholders/CONTEXT.md
  마스터 매트릭스 [김영희] 행:
  변경 전: 참여
  변경 후: 불참

📄 harnesses/shareholders/STATUS.md
  구주 확보 현황: 재계산 필요

진행할까요?
```

### Step 4. 업데이트 실행

확인 받으면 즉시 파일 업데이트.

MT-5의 경우 WWG 최대주주 마진 자동 재계산:
- WWG 총 취득 - UTC 합산 = 마진
- 마진 +100,000주 미만 시 ⚠️ 경고 출력
- 경고 시 루트 `STATUS.md` "미해결 사항"에 자동 추가

### Step 5. 완료 보고

```
✅ 업데이트 완료 (2026-05-29)

- harnesses/shareholders/per-holder/김영희.md — 구주 의향: 불참
- harnesses/shareholders/CONTEXT.md — 매트릭스 갱신
- harnesses/shareholders/STATUS.md — 확보 현황 재계산

⚠️ WWG 마진: +87,000주 (기준치 미달)
→ 루트 STATUS.md 미해결 사항에 추가됨
```

## 파일별 업데이트 가이드

### per-holder/<주주>.md 표준 6개 섹션

업데이트 시 다음 섹션 구조를 유지한다:

```markdown
# [주주명]

## 1. 기본 정보
## 2. 보유 주식 현황
## 3. 구주 처리 의향
## 4. 커뮤니케이션 이력
## 5. 주요 조건/요구사항
## 6. 미해결 사항
```

변경 사항은 해당 섹션에 날짜와 함께 기록:
```
YYYY-MM-DD: [변경 내용]
```

이전 상태는 삭제하지 않고 취소선 또는 히스토리 형태로 보존한다.

### CONTEXT.md 마스터 매트릭스

shareholders 전용. 주주별 현황 테이블의 해당 행을 업데이트한다. 테이블 전체 합산이 필요한 경우 재계산 후 업데이트.

### STATUS.md

날짜가 박힌 휘발성 상태(지금 상태)만 업데이트한다. 형식:
```
[YYYY-MM-DD] [변경 내용]
```

grill-setup이 만든 STATUS.md는 `목표 / 핵심 마감 / 현재 상태 / 다음 액션 / 미해결 사항` 섹션을 가진다. 변경은 `현재 상태`에, cross-cutting 이슈는 `미해결 사항`에 박는다. 해당 섹션이 없으면 만든다.

### history 파일 (히스토리를 쌓는 프로젝트)

`docs/agents/domain.md`에 히스토리 위치가 정의돼 있으면(루트 `history/<YYYY-MM>.md` / `<group>/history/` / `docs/knowledge/history*`), 지나간 사건·지표·결정은 STATUS.md(지금 상태)가 아니라 **해당 월 history 파일에 append**한다. 과거 항목은 보존. 같은 변경이 "지금 상태"이면서 "기록"이기도 하면 둘 다 갱신한다.

## "나중에" 선택 시

즉시 인터럽트에서 "나중에"를 선택하면:
- grill-knowledge 큐에 추가 (MT-5 또는 고중요도 MT-2로 표시)
- 세션 종료 시 펼침 목록에 **⚡ 표시** (일반 후보와 구분)

단, MT-5(주주 입장 변경)는 "나중에"를 선택해도 세션 중 한 번 더 remind한다:

> "세션 종료 전 알림: [주주] 입장 변경이 아직 반영되지 않았습니다. 지금 처리하시겠어요?"

사용자가 "grill-sync 돌려", "이거 바로 업데이트해줘" 등으로 직접 호출하면:

1. 어떤 사실이 바뀌었는지 설명해달라고 요청
2. 위 플로우 동일하게 진행
